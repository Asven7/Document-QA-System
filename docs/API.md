# API Documentation - Document QA System

Practical, copy-paste-ready documentation for the REST API. The same
endpoints are also documented interactively in **Swagger UI** at
[`/api/docs/`](http://localhost:8000/api/docs/) (OpenAPI 3 schema at
[`/api/schema/`](http://localhost:8000/api/schema/)) - generated by
drf-spectacular from the live serializers.

---

## Base URL

```
http://localhost:8000
```

All endpoints are versioned under `/api/v1/`. All request/response bodies
are UTF-8 JSON (except multipart uploads) - Persian text is supported in
every text field.

## Authentication

All business endpoints require a token. Obtain one with your Django
username/password:

```bash
curl -X POST http://localhost:8000/api/auth/token/ \
  -H "Content-Type: application/json" \
  -d '{"username": "admin", "password": "admin123"}'
```

```json
{
  "token": "9944b09199c62bcf9418ad846dd0e4bbdfc6ee4b",
  "username": "admin"
}
```

Then send it with every request:

```bash
TOKEN=9944b09199c62bcf9418ad846dd0e4bbdfc6ee4b
curl http://localhost:8000/api/v1/documents/ -H "Authorization: Token $TOKEN"
```

| Endpoint | Auth | Notes |
| --- | --- | --- |
| `GET /api/health/` | public | service health |
| `POST /api/auth/token/` | public | obtain token |
| `/api/docs/`, `/api/schema/` | public | Swagger UI / OpenAPI |
| everything under `/api/v1/` | **Token** | `401` without it |

Below, `$TOKEN` always means the `Authorization: Token …` header.

## System

### Health check

```bash
curl http://localhost:8000/api/health/
```

```json
{
  "status": "ok",
  "database": { "status": "ok" },
  "vector_store": { "status": "ok", "indexed_chunks": 12 },
  "embedding": {
    "provider": "fastembed",
    "model": "Qwen/Qwen3-Embedding-0.6B-Q",
    "cache_path": "/app/model_cache",
    "offline_mode": true,
    "loaded_in_process": true
  },
  "llm": {
    "configured": true,
    "model": "meta-llama/llama-3.3-70b-instruct:free"
  }
}
```

A missing LLM key does **not** make the service unhealthy (`llm.configured:
false`) - document management stays usable. The `embedding` block reports
the configured provider/model, the persistent cache path, whether the web
container is restricted to the local model cache (`offline_mode`), and
whether the model is already loaded in the serving process
(`loaded_in_process`).

## Documents

### Create a document

Documents are **text-centric**. Provide exactly one content source - a DOCX
upload or the raw text. Only the text is stored: a DOCX upload is parsed in
memory and the binary file is never persisted.

**Option A - upload a DOCX file (multipart):**

```bash
curl -X POST http://localhost:8000/api/v1/documents/ \
  -H "Authorization: Token $TOKEN" \
  -F "file=@persian_sample.docx" \
  -F "title=راهنمای کارکنان"
```

**Option B - write/paste the text (JSON or form field):**

```bash
curl -X POST http://localhost:8000/api/v1/documents/ \
  -H "Authorization: Token $TOKEN" -H "Content-Type: application/json" \
  -d '{"title": "سیاست دورکاری", "content": "کارکنان می‌توانند حداکثر ۲ روز در هفته دورکار کار کنند."}'
```

`title` is optional - it defaults to the filename without extension (uploads)
or to the first line of the text (typed content).

**201 Created**

```json
{
  "id": "7c9e6679-7425-40de-944b-e07fc1f90ae7",
  "title": "راهنمای کارکنان",
  "source": "docx",
  "original_filename": "persian_sample.docx",
  "status": "completed",
  "content": "راهنمای کارکنان\n\nمقدمه\n\nاین سند…",
  "content_hash": "ceed6787f70f93867f00468756f0dd53…",
  "chunk_count": 9,
  "error_message": "",
  "uploaded_by": "admin",
  "created_at": "2026-11-03T10:15:00Z",
  "updated_at": "2026-11-03T10:15:01Z"
}
```

`source` is `"docx"` or `"text"`; `original_filename` is empty for typed
documents.

**Validation errors (400)**

| Body | Cause |
| --- | --- |
| `{"non_field_errors": ["Provide either a DOCX file or text content, not both."]}` | both sources given |
| `{"non_field_errors": ["Provide either a DOCX file (multipart) or text content to create a document."]}` | neither given |
| `{"content": ["The document text must not be empty."]}` | empty/whitespace text |
| `{"content": ["…maximum of 500000 characters."]}` | text too long |
| `{"file": ["Unsupported file type. Only .docx files are accepted."]}` | wrong extension |
| `{"file": ["The uploaded file is empty."]}` | 0 bytes |
| `{"file": ["The file exceeds the maximum upload size of 10 MB."]}` | too large |
| `{"file": ["The file does not look like a valid DOCX document (missing ZIP container signature)."]}` | not a ZIP at all |
| `{"file": ["The file is a ZIP archive but not a DOCX document: …"]}` | ZIP without a Word part |

**Duplicate (409)**

```json
{
  "detail": "A document with identical content already exists ('Employee Handbook', id 1f0e…).",
  "existing_document_id": "1f0e9d3a-…"
}
```

> A **truncated/corrupt but DOCX-shaped** file is accepted with
> `201` and `"status": "failed"` plus a readable `error_message` - the row
> stays visible for inspection and retry.

### List documents

```bash
curl "http://localhost:8000/api/v1/documents/?status=completed&page=1" \
  -H "Authorization: Token $TOKEN"
```

Query parameters: `status` (`pending|processing|completed|failed`,
invalid values → 400), `page`, `page_size` (default 20). The list payload
is light - no `content`.

```json
{
  "count": 2,
  "next": null,
  "previous": null,
  "results": [
    {
      "id": "7c9e6679-…",

```

### Retrieve a document

```bash
curl http://localhost:8000/api/v1/documents/7c9e6679-7425-40de-944b-e07fc1f90ae7/ \
  -H "Authorization: Token $TOKEN"
```

Returns the full record incl. `content` and `error_message`.
Unknown id → `404 {"detail": "Not found."}`.

### Update a document

Change only the title (JSON)…

```bash
curl -X PATCH http://localhost:8000/api/v1/documents/7c9e6679-…/ \
  -H "Authorization: Token $TOKEN" -H "Content-Type: application/json" \
  -d '{"title": "راهنمای کارکنان - نسخه ۲"}'
```

…and/or **edit the text content**. Replacing `content` re-runs the whole
pipeline (chunk → embed → reindex); old chunks and vectors are removed
first, so search always reflects the edited text.

```bash
curl -X PATCH http://localhost:8000/api/v1/documents/7c9e6679-…/ \
  -H "Authorization: Token $TOKEN" -H "Content-Type: application/json" \
  -d '{"content": "متن کامل و جدید سند…"}'
```

Empty body → `400`; empty/whitespace text → `400`; duplicate content →
`409`. On success: `200` with the updated detail payload.

### Delete a document

```bash
curl -X DELETE http://localhost:8000/api/v1/documents/7c9e6679-…/ \
  -H "Authorization: Token $TOKEN"
```

`204 No Content`. Chunk rows are cascade-deleted and the corresponding
vectors removed from the index (a `pre_delete` signal also covers Admin
bulk deletes) - deleted content can never appear in later answers.

### Reprocess a document

```bash
curl -X POST http://localhost:8000/api/v1/documents/7c9e6679-…/reprocess/ \
  -H "Authorization: Token $TOKEN"
```

Re-runs chunking/indexing for the stored text - e.g. after changing
`CHUNK_SIZE` or `EMBEDDING_MODEL`. `200` with the document, or
`400 {"detail": "…"}` if embedding fails.

## Questions

### Submit a question

```bash
curl -X POST http://localhost:8000/api/v1/questions/ \
  -H "Authorization: Token $TOKEN" -H "Content-Type: application/json" \
  -d '{"question_text": "How many days of annual leave do employees get?"}'
```

Optional `document_ids` restricts retrieval to specific documents:

```json
{
  "question_text": "مرخصی ازدواج چند روز است؟",
  "document_ids": ["7c9e6679-7425-40de-944b-e07fc1f90ae7"]
}
```

**201 Created** - answer, sources and metadata in one response:

```json
{
  "id": "3f2a…",
  "question_text": "How many days of annual leave do employees get?",
  "answer_text": "Every full-time employee receives 26 days of paid annual leave per calendar year. [Source 1]",
  "status": "completed",
  "model": "meta-llama/llama-3.3-70b-instruct:free",
  "error_message": "",
  "sources": [
    {
      "document_id": "7c9e6679-…",
      "document_title": "Employee Handbook",
      "chunk_id": "9a1b…",
      "chunk_index": 2,
      "rrf_score": 0.032787,
      "semantic_rank": 1,
      "semantic_distance": 0.184,
      "lexical_rank": 1
    }
  ],
  "document_scope": [],
  "asked_by": "admin",
  "created_at": "2026-11-03T10:20:00Z",
  "updated_at": "2026-11-03T10:20:05Z"
}
```

Behaviour details:

- **Language matching** - Persian questions receive Persian answers
  (enforced by the system prompt).
- **No relevant content** - the answer is the honest, localized notice
  ("The uploaded documents do not contain enough information…" /
  «اسناد بارگذاری‌شده حاوی اطلاعات کافی برای پاسخ به این پرسش نیستند.»)
  with `status: "completed"`, `model: ""` and empty `sources` - no LLM call
  is made and nothing is invented.
- **LLM not configured** - `status: "failed"` with
  `error_message` explaining how to set `OPENROUTER_API_KEY`.
- Provider failures (invalid key, rate limit, timeout, model unavailable)
  produce `status: "failed"` with a safe, human-readable `error_message`;
  retrieved `sources` are still included for transparency.

**Validation (400)**

| Body | Cause |
| --- | --- |
| `{"question_text": ["This field is required."]}` | missing question |
| `{"question_text": ["This field may not be blank."]}` | empty/whitespace |
| `{"question_text": ["…at least 3 characters…"]}` | too short |
| `{"document_ids": ["Invalid document id …"]}` | unknown/invalid UUID |

### Question history

```bash
curl "http://localhost:8000/api/v1/questions/?status=completed&search=مرخصی" \
  -H "Authorization: Token $TOKEN"
```

Query parameters: `status` (`completed|failed|…`), `search` (substring
match on the question text, works with Persian), `page`, `page_size`.
Returns the same paginated shape as the documents list.

### Single question

```bash
curl http://localhost:8000/api/v1/questions/3f2a…/ \
  -H "Authorization: Token $TOKEN"
```

Question records are immutable via the API (no PUT/PATCH/DELETE) - history
integrity by design; the Django Admin can be used for cleanup.

## End-to-end example: Persian document → Persian answer

```bash
TOKEN=…   # from POST /api/auth/token/

# 1) Upload the Persian sample document
DOC_ID=$(curl -s -X POST http://localhost:8000/api/v1/documents/ \
  -H "Authorization: Token $TOKEN" \
  -F "file=@sample_data/persian_sample.docx" \
  -F "title=راهنمای کارکنان" | python -c "import sys,json;print(json.load(sys.stdin)['id'])")

# 2) Ask a Persian question scoped to that document
curl -s -X POST http://localhost:8000/api/v1/questions/ \
  -H "Authorization: Token $TOKEN" -H "Content-Type: application/json" \
  -d "{\"question_text\": \"بودجه آموزشی سالانه هر کارمند چقدر است؟\", \"document_ids\": [\"$DOC_ID\"]}"
```

Expected shape of the answer: a Persian sentence grounded in the document
with `[Source N]` citations, plus the `sources` array pointing at the exact
chunks (document id, chunk id, chunk index, ranking scores).

```bash
# 3) Verify the question appears in the history
curl -s "http://localhost:8000/api/v1/questions/?search=آموزشی" \
  -H "Authorization: Token $TOKEN"
```

### Cross-lingual retrieval example

The embeddings are multilingual, so an English question can find Persian
content (and vice versa):

```bash
curl -X POST http://localhost:8000/api/v1/questions/ \
  -H "Authorization: Token $TOKEN" -H "Content-Type: application/json" \
  -d '{"question_text": "How many hours per week must employees work according to the handbook?"}'
```

The Persian handbook chunk about weekly working hours is retrieved
(`sources[0].document_title` = «راهنمای کارکنان») and the model answers in
English.

## Error code summary

| HTTP | When |
| --- | --- |
| 400 | validation errors (fields), invalid filters, processing failures (reprocess), LLM provider errors surfaced on the question record |
| 401 | missing/invalid token |
| 404 | unknown document/question id, missing stored file |
| 409 | duplicate document content |
| 201 | successful upload / question submission |
| 200 | reads, updates, reprocess |
| 204 | successful delete |

Error bodies are always JSON; secrets, provider payloads and tracebacks are
never included.
